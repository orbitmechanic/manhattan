Street centreline stationing — OSM default + legacy sets
======================================================

Default generator
  python3 scripts/build_station_osm.py
  (input viewer/assets/models/street_centrelines.json)

Legacy generator (kept for comparison)
  /tmp/opencode/geoenv/bin/python scripts/build_station_lines.py

Inputs
  street_centrelines.json          1,814 merged OSM chains, 431.5 km
  build/building_mask.png          2 m building footprint mask
  build/blocks.json                bounds
  Textures/day/ground/satellite_manhattan_ground.jpg (1792x1024)

Set C — OSM STREETS (1814 lines, 268.1 miles, 16873 ticks; default)
  - Real OpenStreetMap centerlines from street_centrelines.json.
  - Ways are merged by name + endpoint continuity and clipped to the model
    ground; bridges and tunnels are excluded because the city mesh has no
    deck geometry.
  - Ticks are interpolated every 100 ft along each chain.
  - Plan curves/tangents are empty and the vertical profile is grade 0
    because the model ground is flat.  The schema is preserved for future
    elevation work.
  - This is the default stationing overlay and civil-coordinate set.

Set A — IMAGERY (2041 lines, 92.1 miles, 8003 ticks; legacy)
  - Resample the satellite to the 2 m building-mask grid.
  - Road pixels: low saturation (<0.16), value 0.22..0.82, outside buildings.
  - Skeletonise the free-space mask and keep skeleton pixels that fall on
    road-coloured ground, 4..30 m from a building.
  - Trace with straight-through continuation at junctions; simplify (RDP 3 m);
    drop lines under 30 m.

Set B — BUILDING FRONTS (2460 lines, 185.5 miles, 13513 ticks; legacy)
  - Label every individual building component.
  - Compute the nearest building component for every free pixel with a
    Euclidean distance transform.
  - The boundary between two different nearest components is where the
    simultaneous expansion fronts of those buildings meet; that locus is the
    road centreline estimate.
  - Keep the front only while it is 1..35 m from a building, skeletonise,
    trace straight through junctions, simplify (RDP 2 m), drop lines under
    25 m.

Line data (all sets)
  id, points [[x,z],...] in viewer coordinates, length_m/length_ft
  station_start_ft, station_end_ft, ticks_ft, tick_points [[x,z],...]
  plan_curves[] { start/end station, radius_ft, turn_deg, direction, reverse }
  plan_tangents[] { start/end station }
  vertical { tangent_points_ft, grades, curves, start/end_elevation_ft }
  Stations/offsets/elevations in feet; geometry in metres.

Viewer
  station_lines_imagery.json / station_lines_fronts.json / station_lines_osm.json
  are compiled into the app.  src/stationing.rs:
    - draws the selected set (L), 100-ft vertical ticks from -3 m to +30 m (T);
    - maintains one compact nearest-coordinate array for the active set
      (up to 8 entries): station_ft, offset_ft (negative left / positive right
      up-station), elevation_ft, plan_distance_ft, nearest tangent
      station/elevation, station_from_tangent_ft, elevation_from_tangent_ft;
    - refreshes ~4x/s while moving and 0.2x/s while stationary, and only for
      the selected set; switching sets recomputes immediately;
    - shows the three nearest lines for the selected set in the panel;
    - G (or the set [G] button) cycles IMAGERY -> BUILDING FRONTS -> OSM
      STREETS.
    OSM STREETS is the default and the HUD reports 1,814 lines / 268.1 mi.
  Keys: L lines, T ticks, C civil-coordinate panel, G set.
  Web: ?lines=1&ticks=1&set=imagery|fronts|osm (the default is osm).

Caveat
  The OSM set is real street geometry (ODbL) rather than a heuristic, but it
  is still a planning aid, not a legal survey.  The legacy imagery/front sets
  remain available only for comparison; they are no longer the default.
