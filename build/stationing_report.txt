Street centreline stationing — two sets
=====================================

Generated by
  /tmp/opencode/geoenv/bin/python scripts/build_station_lines.py

Inputs
  build/building_mask.png              2 m building footprint mask
  build/blocks.json                    bounds
  Textures/day/ground/satellite_manhattan_ground.jpg (1792x1024)

Set A — IMAGERY (2041 lines, 92.1 miles, 8003 ticks)
  - Resample the satellite to the 2 m building-mask grid.
  - Road pixels: low saturation (<0.16), value 0.22..0.82, outside buildings.
  - Skeletonise the free-space mask and keep skeleton pixels that fall on
    road-coloured ground, 4..30 m from a building.
  - Trace with straight-through continuation at junctions; simplify (RDP 3 m);
    drop lines under 30 m.

Set B — BUILDING FRONTS (2460 lines, 185.5 miles, 13513 ticks)
  - Label every individual building component.
  - Compute the nearest building component for every free pixel with a
    Euclidean distance transform.
  - The boundary between two different nearest components is where the
    simultaneous expansion fronts of those buildings meet; that locus is the
    road centreline estimate.
  - Keep the front only while it is 1..35 m from a building (removes harbour
    and open-water boundaries), skeletonise, trace straight through junctions,
    simplify (RDP 2 m), drop lines under 25 m.

Set C — COMPLETED (4445 lines, 189.1 miles, 16894 ticks; default)
  - Start from the building-front skeleton, drop hair fragments under 400 m².
  - Connect every remaining component with a minimum spanning tree of
    free-space paths.  Buildings are impassable; connectors prefer road-coloured
    pixels and stay out of the harbour.
  - Re-vectorise the connected skeleton at 1.0 m RDP tolerance, prune short
    spurs, and add explicit line-level connectors for any remaining vector gap.
  - Smooth each completed line with two 3-point passes that preserve corners
    sharper than 25 degrees, then simplify at 0.15 m.  Smoothed segments that
    enter a building are rejected in favour of the original polyline.
  - This is the set intended for selecting which graphics elements to display;
    it is connected, while the two source sets remain available for comparison.

Line data (both sets)
  id, points [[x,z],...] in viewer coordinates, length_m/length_ft
  station_start_ft, station_end_ft, ticks_ft, tick_points [[x,z],...]
  plan_curves[] { start/end station, radius_ft, turn_deg, direction, reverse }
  plan_tangents[] { start/end station }
  vertical { tangent_points_ft, grades, curves, start/end_elevation_ft }
  Stations/offsets/elevations in feet; geometry in metres.
  Current vertical profiles are grade 0 (source ground is flat) but carry the
  tangent/curve schema for future elevation work.

Viewer
  station_lines_imagery.json / station_lines_fronts.json / station_lines_completed.json
  are compiled into the app.  src/stationing.rs:
    - draws the selected set (L), 100-ft vertical ticks from -3 m to +30 m (T);
    - maintains separate camera coordinate arrays for both sets:
      station_ft, offset_ft (negative left / positive right up-station),
      elevation_ft, plan_distance_ft, nearest tangent station/elevation,
      station_from_tangent_ft, elevation_from_tangent_ft;
    - shows the three nearest lines for the selected set in the panel;
    - G (or the set [G] button) cycles IMAGERY -> BUILDING FRONTS -> COMPLETED.
    COMPLETED is the default.
  Keys: L lines, T ticks, C civil-coordinate panel, G set.
  Web: ?lines=1&ticks=1&set=imagery|fronts.

Caveat
  Both networks are planning aids, not surveys.  The imagery set inherits the
  satellite resolution and road-colour thresholds; the front set inherits the
  building footprint mask and treats meeting fronts as centreline estimates.
  Field-check before construction.
